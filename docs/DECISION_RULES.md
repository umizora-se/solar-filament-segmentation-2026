# 提出判断のルール（実測から導いたもの）

- 作成日時: 2026-09-08 20:10 JST
- 改訂: 2026-11-09 ルール1を変更（+0.005 未満でも汎化の改善が確かなら採用）
- きっかけ: val-PQ を上げた提出（0.4322→0.4331）で LB が下がった（0.40→0.39）

---

## 1. 何が起きたか

| 提出 | val-PQ | LB |
|---|---|---|
| submission_arch（検証器3種） | 0.4322 | **0.40** |
| submission_verexp（検証器4種） | 0.4331（+0.0009） | 0.39（−0.01） |

val-PQ と LB が初めて逆方向に動いた。それまで3回連続で同方向だったため、
val-PQ を過信していた。

## 2. 原因

### (a) 差が測定誤差より小さかった

val は fold 0 の 142枚。+0.0009 という差はこの標本サイズでは区別できない。
「改善」ではなく「同じ」と読むべきだった。

### (b) val 上での探索を重ねた

施策1のメンバー選択は、11候補から4つを選ぶ貪欲前進選択を **val の AUROC で**
行った。選択の自由度が高いほど val に過適合する。
後処理のグリッド探索も同じ val で行っており、探索が二重に重なっていた。

## 3. 今後のルール

1. **+0.005 は目安とし、未満でも汎化の改善が確かなら採用する。** fold0（142枚）だけの
   +0.005 未満の差は測定誤差を下回るため、OOF 707枚で次を確認する
   - 運用点の後処理で、大半の fold が改善している（特定の fold に依存していない）
   - 画像単位のブートストラップで、差の 95% 信頼区間が 0 を上回る
   - 多数の候補から最良を拾っただけの結果ではない（ルール2）
2. **val 上で探索（貪欲選択・グリッド・モード選択）を重ねた結果は割り引く。**
   探索の自由度が大きいほど、val の改善は本物でない確率が上がる
3. **性質の違う変更（データ量・アーキ・学習レシピ）は、val で選択を重ねていない
   限り、val 差が小さくても試す価値がある**（施策3の全データ学習はこれに該当）
4. LB は小数2桁に量子化されているため、**LB の 0.01 差は val の 0.005 相当**と
   考えて対応づける
